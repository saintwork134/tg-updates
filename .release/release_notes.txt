TG Mass Sender v2.8.54

- Daily limits expire at the next calendar midnight, not 24 hours after the limit.
- A running cycle refreshes its day baseline after midnight.
- Startup keeps daily/hourly limited accounts in the scheduler until their rest expires.
- Partial or absent Telegram profiles cannot overwrite Premium as absent.
- Invalid database statements no longer discard valid neighbouring queued writes.
- Storage failures retain the in-flight batch; flush no longer reports rejected writes as successful.
- Failed immediate database transactions roll back before another operation uses the connection.
- Proxy prechecks run outside the asyncio event loop; failed sockets close deterministically.
- Connection and authorization checks in cycles have explicit deadlines.
- Recovered FloodWait clears only its own automatic rest, preserving later manual decisions.
- Retry media operations use the same global resource pool as normal operations.
- Partial, busy and cancelled status checks are not logged as full success.
- Permission and deletion-check errors include RPC/error types and codes.
- Resource diagnostics include per-client update backlog, entity cache and task counts.
- Removed mutation of Telethon private caches during disconnect.
- Calendar rules are isolated in a small, independently tested module.
- Packaging runs regression tests and the isolated GUI smoke check, even with --skip-build.

Validation uses fake clients, temporary databases and simulated calendar time.
No live customer messages are sent by tests. Real 24-hour memory profiling remains necessary.
This release does not replace the entire session architecture with persistent account actors.
